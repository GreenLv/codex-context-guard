# Context Guard 0.14.0

## English

### Highlights

- Keep future benefit observations out of the current task while retaining unfinished tests and evaluations that the user requested now.
- Resume only sourced, ready work; a short “continue” does not create an unlimited persistence demand or an external wait.
- Let the Codex host perform ordinary edits and tests while Guard checks their persisted results and independent readback. Explicit proof and adopted release protection remain in force.

### Upgrade

Use the managed installer after confirming the published version. Start a fresh task, trust all nine Hooks through `/hooks`, then start another fresh task to load the new version. Keep consumed versioned caches for existing tasks. Host Goal-completion interception remains unavailable until its synchronous Hook path is verified; explicit proof and whole-completion checks still apply.

### Validation boundary

The changelog and [local acceptance record](https://github.com/GreenLv/codex-context-guard/blob/v0.14.0/docs/LOCAL_ACCEPTANCE.md) distinguish source checks, CI, macOS and Windows native results, fixed-model observations, installation and public readback. The exact release commit and annexes must be checked separately; older candidate results cannot certify changed runtime bytes.

See the [full English changelog](https://github.com/GreenLv/codex-context-guard/blob/v0.14.0/CHANGELOG.md).

## 简体中文

### 要点

- 长期收益的后续观察不再变成当前待办；用户现在要求而尚未完成的测试和评估仍被保留。
- 简短“继续”只推进有来源且已就绪的工作，不会制造无限持续要求或外部等待。
- 普通编辑和测试由 Codex 宿主执行，Guard 核验已持久化的结果与独立回读。显式 proof 和已采用的 release 保护继续有效。

### 升级

确认正式版本已发布后使用受管安装器。新建任务，在 `/hooks` 中信任全部九项 Hook，然后再新建任务加载新版。旧任务使用的版本化缓存应保留。宿主 Goal 完成拦截在同步 Hook 路径核验前仍不可用；显式 proof 与整体完成检查继续有效。
