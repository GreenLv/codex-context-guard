# Context Guard 0.13.3

## English

### Highlights

- Ordinary commits and single branch pushes no longer depend on readable private release state. If an active release ledger is damaged, follow-on work in the current or another repository can still continue.
- Publication remains protected. Tags, package uploads, GitHub Releases, mutation runners and restricted compound calls still require verified release state when the release profile is active.
- This is a compatible patch with no schema, protocol, activation or host-permission change. Existing 0.13.2 caches remain unchanged; run the managed installer and start a fresh task to load 0.13.3.

### Validation

Source checks passed 1,079 current-behavior tests on macOS. Exact commit `7e5212e` passed Candidate CI on Ubuntu, macOS and Windows with Python 3.10–3.13, the required summary, HOL, and independent portable checks on macOS and Windows. All five portable gates and cleanup passed on each native platform. The final documentation-only freeze does not change plugin runtime bytes and is checked separately by exact-commit CI and HOL before tagging. The 0.13.2 real-host results keep their original identity and are not 0.13.3 evidence. See the [acceptance boundaries](https://github.com/GreenLv/codex-context-guard/blob/v0.13.3/docs/LOCAL_ACCEPTANCE.md).

## 简体中文

### 重点

- 普通提交和单次分支推送不再依赖可读取的私有发布状态。已启用发布模式的账本即使损坏，当前仓库或同一任务中其他仓库的后续工作仍可继续。
- 发布操作继续受保护。发布模式启用时，tag、包上传、GitHub Release、通过命令运行器执行的变更和受限制的复合调用仍须通过发布状态核验。
- 这是兼容性补丁，不改变 schema、协议、启用条件或宿主权限。已有 0.13.2 缓存保持不变；请运行受管安装器，并启动新任务加载 0.13.3。

### 验证

源码检查在 macOS 上通过 1,079 项 current-behavior 测试。精确提交 `7e5212e` 已通过 Ubuntu、macOS、Windows 的 Python 3.10–3.13 Candidate CI、必需汇总门、HOL，以及独立 macOS/Windows portable 检查；两个原生平台的五项 portable 门禁与清理均通过。最终文档冻结不改变插件运行时字节，打 tag 前另由自身精确提交 CI 与 HOL 核验。0.13.2 的真实宿主结果保留原版本身份，不作为 0.13.3 证据。详见[验收边界](https://github.com/GreenLv/codex-context-guard/blob/v0.13.3/docs/LOCAL_ACCEPTANCE.md)。
