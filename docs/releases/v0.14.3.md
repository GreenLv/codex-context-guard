# Context Guard 0.14.3 — 2026-09-29

## English

### Highlights

- Long conversations finish Stop evaluation faster while retaining completion and recovery checks. The incident-shaped macOS full-process median fell from 7.252 s to 0.472 s; native Windows measured 0.489 s on the candidate.
- If a source record changes during Stop evaluation, the commit fails and business-state changes from that event are rolled back. Failed integrity checks cannot leave completed units or accepted proofs persisted as success.
- Answered bounded Chinese why-questions stay out of recovery debt. Mixed requests such as “解释模块为什么失败再修复模块” retain their execution work; ambiguous tails remain open.
- Historical coverage now has 37 passed active records and 15 Codex-side DSH analogues, with no Windows process rows pending. The analogues do not certify DSH itself.

### Changes

- Reuses parsed text and validated records within one event, discarding reusable state at each mutation boundary. No cache crosses events.
- Keeps schema 13, Stop 5.0.0 and all nine Hooks. No state migration is required. Use the managed installer, preserve consumed 0.14.2 caches, then review and trust the nine Hooks in a fresh task and start another task to load the new version.
- This release's host acceptance targets Codex CLI 0.158.0. Old CLI versions are not retested.

### Validation

- Source and historical-library checks, macOS isolated install/no-op/lifecycle smoke, and Windows W1–W7 process gates passed. Windows subprocess replay remains distinct from model and host scheduling.
- Separate bounded macOS and Windows live-host batches passed: completed Stop runs, an expected correction, real compaction and cold continuation with pending work preserved. These synthetic scenarios do not reproduce the original incident state or certify universal host behavior. Exact-commit CI/HOL, tag and public Release readback are separately verified publication gates. See the [acceptance record](../LOCAL_ACCEPTANCE.md) for timing scopes and retained failed attempts.

## 简体中文

### Highlights

- 长会话的 Stop 评估明显加快，完成与恢复检查仍然保留。事故形状夹具在 macOS 上的全进程中位耗时从 7.252 秒降至 0.472 秒，候选在原生 Windows 上为 0.489 秒。
- 源记录在 Stop 评估中途发生变化时，提交失败并回滚本次事件的业务状态改动。完整性检查失败后，已关闭单元或已接受证明不会作为成功结果留在磁盘上。
- 已回答的有界中文 why 疑问不再回到恢复待办。“解释模块为什么失败再修复模块”等混合请求仍保留执行工作，有歧义的尾句保持未闭合。
- 历史覆盖表已有 37 条活动记录通过、15 条 Codex 侧 DSH 类比验证，Windows 进程验收待办为零；类比结果不认证 DSH 本身。

### Changes

- 在一次事件内复用文本解析和已验证记录，每次状态改写后使相关复用结果失效；没有跨事件缓存。
- Schema 13、Stop 5.0.0 和九个 Hook 不变，无需迁移状态。使用受管安装器并保留已消费的 0.14.2 缓存；升级后在新任务中检查并信任九个 Hook，再启动另一任务加载新版。
- 本版宿主验收面向 Codex CLI 0.158.0，不补测旧 CLI。

### Validation

- 源码与历史错误库检查、macOS 隔离安装/no-op/生命周期 smoke、Windows W1–W7 进程门槛通过。Windows 子进程重放与真实模型、宿主调度分别记录。
- macOS 与 Windows 各自的有界真实宿主批次通过：Stop 正常完成、预期纠正、真实压缩与冷恢复后待办保留。合成场景不复现原始事故全状态，也不认证所有宿主行为。精确提交的 CI/HOL、tag 与公开 Release 读回作为发布门槛单独核验。计时口径与保留的失败尝试见[验收记录](../LOCAL_ACCEPTANCE.md)。
