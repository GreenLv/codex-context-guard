# Context Guard 0.14.2

## English

### Highlights

- File names, paths and quoted text stay object data: renaming a test directory to `audit` or `commit` does not erase an existing request to continue the test.
- Recovery separates observed business results from remaining work, waits and unknown evidence. A successful edit readback does not prompt a repeat edit.
- Offline batch preflight catches missing initial commits, reused composite sessions, mismatched input digests and inconsistent timeout budgets before model execution.

### Changes

- Adds source-bound commentary observation, independent answer review and byte-exact confirmation waits while keeping ordinary business tools under Codex's authority.
- Keeps private schema 13, Stop 5.0.0 and all nine Hook events. Install changed runtime bytes in a new versioned cache; preserve consumed 0.14.1 caches. After upgrading, review and trust the nine Hooks in a fresh task, then start another task to load them.

### Validation

- Source commit `514f41d67d8be3930aaa63450456a0a5c375e9d0` passed the [12-lane Candidate CI matrix](https://github.com/GreenLv/codex-context-guard/actions/runs/36089305152) and [HOL scan](https://github.com/GreenLv/codex-context-guard/actions/runs/36089304966). Publication requires green CI/HOL for the exact release commit; their receipts are recorded separately.
- Separate macOS and Windows complete-answer, partial-answer and exact-marker controls passed scoped zero-model replays against bounded native runs. Original collectors retain their narrower verdicts; whole-task closure, actual compaction-threshold calibration and escaped-descendant absence are not established. Three original historical cases remain unresolved under the user-approved release scope; none is claimed fixed or passed. See the [acceptance record](../LOCAL_ACCEPTANCE.md).

## 简体中文

### Highlights

- 文件名、路径和引文保留为对象数据：把测试目录改名为 `audit` 或 `commit`，不会抹掉既有的持续测试要求。
- 恢复信息区分已观察的业务结果、剩余工作、等待与未知证据。编辑和回读已成功时，不会催促重复编辑。
- 离线批次预检在模型执行前识别缺失初始提交、复用的组合会话、输入摘要不符及超时预算不一致。

### Changes

- 加入有来源绑定的进度观测、独立答案审读和逐字节确认等待；普通业务工具仍由 Codex 负责。
- 私有 schema 13、Stop 5.0.0 及九个 Hook 事件不变。变化的运行时须安装到新的版本化缓存，已消费的 0.14.1 缓存保持不变。升级后在新任务中检查并信任九个 Hook，再启动另一任务加载新版。

### Validation

- 源码提交 `514f41d67d8be3930aaa63450456a0a5c375e9d0` 的 [12 通道 Candidate CI](https://github.com/GreenLv/codex-context-guard/actions/runs/36089305152)和 [HOL 扫描](https://github.com/GreenLv/codex-context-guard/actions/runs/36089304966)通过；正式发布须有精确发布提交的绿色 CI/HOL，回执另行记录。
- macOS 与 Windows 各自的完整回答、部分回答及精确口令控制，在有界原生运行后通过限定范围的零模型重放。原始采集器保留较窄的结论；整体任务闭包、实际压缩阈值校准和逃逸后代进程不存在均未证实。依用户批准的发布范围，三项原始历史案例继续未决，均不宣称已修复或通过。详见[验收记录](../LOCAL_ACCEPTANCE.md)。
