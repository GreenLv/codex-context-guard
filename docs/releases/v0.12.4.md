# Context Guard 0.12.4

## English

### Highlights

- Finishing a child task or local phase no longer claims completion of the current task. Missing attachments or external results keep obligations pending; a real whole-task claim still requires evidence even alongside an unrelated wait.
- Follow-up instructions keep the unfinished task and its original limits. Operational correction wording, “do not switch tasks,” quoted examples and plan tables no longer move those limits into history or ask which requirement to replace.
- A confirmation releases only the matching pause. “The model is ready” does not clear a separate file-check pause; unrelated replies, unmet conditions and ambiguous confirmations keep waiting.
- Recovery puts current obligations first and offers complete text in pages tied to the requested session. Long requirements retain their suffix constraints, and a changed scope invalidates old page cursors.
- Commit-and-push follows the authorized source objects, without absorbing unrelated dirty files. A push re-authorization that names the current candidate commit now binds that existing commit and its exact SHA instead of creating an impossible future-commit transition.


### Changes

- Private state advances to schema 11. Schemas 10 and 9 migrate; schemas 7/8 remain read-only. Schema 11 cannot be written back lossily as schema 10.
- Upgrade through the managed installer and start a fresh task to load the new version. Previously consumed 0.12.2 and 0.12.3 caches remain immutable for open tasks. Nine Hook events and the Python 3.10+ standard-library runtime remain supported.

### Validation

The recorded runtime passed independent macOS and Windows portable acceptance and six-gate host composites, preserving original sessions and executable-evidence limits. Source checks, final-commit Candidate CI and HOL, installation, and public tag/Release readback are separate evidence surfaces. The [acceptance record](https://github.com/GreenLv/codex-context-guard/blob/v0.12.4/docs/LOCAL_ACCEPTANCE.md) retains their subjects and boundaries.

## 简体中文

### 重点

- 子任务或局部阶段结束不再被当作当前任务整体验收完成。等待附件或外部结果时保留待办；真正宣称整体完成仍检查证据，另一项等待不能绕过检查。
- 补充指令保留当前未完成任务及原有限制。操作性修正措辞、“不要换题”、引用示例和计划表格不再把这些限制错误移入历史，也不会要求指出要替代哪条要求。
- 确认只解除对应的暂停。“模型已换好”不会解除另一条文件校验等待；无关回复、尚未满足的条件和对象不明确的确认继续保持等待。
- 恢复内容优先列出当前义务，并按指定会话分页读取完整正文。长要求的尾部限制不会丢失；适用范围变化后，旧游标失效。
- 提交并推送遵循获授权的源码对象，不吸收无关脏文件。重新授权推送“当前候选提交”时，运行时现在绑定这个已有提交及其精确 SHA，不再误建一个不可能完成的未来提交转换。


### 变更

- 私有状态推进到 schema 11；schema 10、9 可迁移，7/8 保持只读。禁止把 schema 11 有损写回 schema 10。
- 通过受管安装器升级后，启动新任务加载新版。此前已消费的 0.12.2、0.12.3 缓存保持不可变，供已有任务继续使用。继续支持九个 Hook 和 Python 3.10+ 标准库运行时。

### 验证

已记录的运行时通过 macOS、Windows 独立 portable 验收及各自六门禁宿主组合，保留原始会话和可执行文件证据边界。源码检查、最终提交的 Candidate CI 与 HOL、安装，以及 tag/Release 公开读回分别记录证据；[验收记录](https://github.com/GreenLv/codex-context-guard/blob/v0.12.4/docs/LOCAL_ACCEPTANCE.md)保留各自对象与边界。
