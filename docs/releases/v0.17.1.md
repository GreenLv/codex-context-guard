# Context Guard 0.17.1 — source candidate (unreleased)

Public availability is determined by the GitHub Release readback. Source,
native, artifact, CI and HOL results have separate identities; until that
readback exists, this version is an unreleased source candidate and every
gate below that is not yet executed remains pending.

## English

### Highlights

- The supported upgrade routes to the stable marketplace identity are
  maintained and executable end to end: the 0.16.1 wrapper identity moves to
  the stable identity, the stable identity upgrades in place (0.17.0 →
  0.17.1), and the historical 0.15.1 route stays covered by its declared
  contract. The repository now maintains the native upgrade acceptance
  toolkit and the Windows fixed regression suite that verify these routes.
  See the [upgrade guide](../UPGRADE_0_17_1.md).
- Guard private task state gains a supported, read-only-by-default migration
  path (`inventory → plan → apply → verify → restore`): sessions move
  copy-only into the stable identity's data root, a same-id conflict with
  different content is isolated outside the data root instead of being
  overwritten by timestamps, and a compensating restore removes exactly what
  one run created. Legacy `sessions` trees are never migrated.
- Compatibility boundaries are unchanged: schema 13, Stop protocol 5.0.0,
  the nine Hook events, and the default business-tool path without execution
  approval stay as released in 0.17.0, and installing or upgrading still
  migrates no session data or consumed cache.

### Changes

- Version metadata advances to 0.17.1; changed metadata bytes require a
  fresh artifact identity and consumed 0.17.0 caches stay immutable.
- The native upgrade acceptance toolkit binds the exact old/new pair a round
  verifies through explicit module constants, including the stable-identity
  in-place route; a release round rebinds them in its own tool commit. Thin
  POSIX sh and PowerShell 5.1/7 launchers dispatch to the same testable
  toolkit cores, and the Windows fixed regression suite now covers the
  process-cwd/PowerShell-location separation and the OWNER-RIGHTS versus
  explicit-user-SID distinction alongside the previously pinned cases.
- The performance contract and its thresholds are unchanged; no gate is
  relaxed.

### Validation

- Source-level acceptance on the candidate commit: full behavior suite,
  repository and privacy audits, phase-transition audit, runtime self-test,
  Ruff, compile and whitespace checks, plus the historical error library
  executed case by case on the development platform.
- Native macOS and Windows behavior, exact-artifact installation and
  upgrade, the state migration and recovery drills, CI, HOL and publication
  remain separate pending gates for this candidate.

## 简体中文

### 要点

- 到稳定市场身份的受支持升级路线完整可执行：0.16.1 包装身份迁移到稳定身份、稳定身份原地升级（0.17.0 → 0.17.1），历史 0.15.1 路线继续按已声明合同覆盖。仓库现在维护验证这些路线的原生升级验收工具与 Windows 固定回归套件。见[升级指南](../UPGRADE_0_17_1.zh-CN.md)。
- Guard 私有任务状态获得默认只读的受支持迁移路径（`inventory → plan → apply → verify → restore`）：会话以纯复制方式进入稳定身份的数据根；同 ID 不同内容的冲突隔离到数据根之外，绝不按时间戳覆盖；补偿性恢复只撤销单次运行创建的路径。旧版 `sessions` 目录永不迁移。
- 兼容边界不变：schema 13、Stop 协议 5.0.0、九个 Hook 事件与无执行审批的默认业务工具路径保持 0.17.0 发布行为；安装或升级仍不迁移任何会话数据或已消费缓存。

### 变更

- 版本元数据推进到 0.17.1；元数据字节变化要求新的制品身份，已消费的 0.17.0 缓存保持不可变。
- 原生升级验收工具通过显式模块常量绑定每轮验证的精确新旧配对（含稳定身份原地路线）；发布轮在自己的工具提交里重新绑定。新增 POSIX sh 与 PowerShell 5.1/7 薄启动器调用同一批工具核心；Windows 固定回归套件补齐进程 cwd 与 PowerShell 位置分离、OWNER RIGHTS 与显式用户 SID 区别两项。
- 性能合同与门槛不变；未放宽任何门槛。

### 验证

- 候选提交的源码级验收：完整行为套件、仓库与隐私审计、阶段转换审计、运行时自测、Ruff、编译与空白检查，以及在开发平台逐案执行的历史错误库。
- 原生 macOS/Windows 行为、精确制品安装与升级、状态迁移与恢复演练、CI、HOL 与发布仍为本候选的独立待验门槛。
