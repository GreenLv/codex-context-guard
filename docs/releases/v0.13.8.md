# Context Guard 0.13.8 — source candidate

## English

Unreleased candidate; this is the proposed release body, not a publication record.

### Highlights

- Keep unfinished execution requests in recovery even when an explanation comes first: “list the files then delete temporary files” cannot close on an answer alone.
- Persist `SessionEnd` state through the core within Codex CLI's three-second limit. The Windows launcher skips broken optional Python probes and the extra router process; the expired-session cleanup gate still needs a complete host readback.
- A delivered explanation can close a supported reply-only request, including “how do I publish a version?”. Operation names inside a how-to explanation no longer create unfinished work by themselves.
- Preserve validation requests phrased politely or as questions. After an explicit request to continue, a reply that still proposes authorized assistant work receives at most one correction; genuine user and external waits remain available.
- Reuse an already logged-in isolated HOME across candidate checkouts: the installer can migrate a verified older managed marketplace staging root.

### Upgrade and limits

Use the managed installer and start a fresh task after upgrading; keep old caches for open tasks. No schema, public protocol, default tool-approval or release-enforcement change is required. Existing unanswered records are not retrospectively certified.

The unpublished HOL scanner and manual registry-refresh updates remain included. Consumed 0.13.6 and 0.13.7 caches stay immutable; 0.13.7 did not pass Windows host cleanup and is not a release.

Windows native acceptance can opt into a private Hook boundary trace. It records start/end, elapsed milliseconds and exit code only; a missing end record is a failed or interrupted boundary, never completion proof.

Automatic answer closure accepts a bounded set of English/Chinese request forms. Unknown trailing instructions stay pending, as does unsupported topic wording, including some complex pure consultations. Reply delivery does not establish that an answer is correct. Bounded continuation feedback cannot repair Codex context recovery when the reply no longer identifies remaining work.

### Validation

The source regressions exercise mixed requests, how-to topics, unknown verbs and connectors, acceptance constraints, and compaction recovery. Source, isolated installation, native trusted-Hook behavior, CI and publication are separate checks; see the [acceptance record](../LOCAL_ACCEPTANCE.md) for current results.

## 简体中文

未发布候选；以下为拟发布正文，不表示已经发布。

### Highlights

- 讲解后还有执行工作时，恢复包继续保留待办。例如“列出文件后删除临时文件”不能仅凭一条答复关闭。
- `SessionEnd` 在 Codex CLI 的三秒上限内直接运行核心并写入结束状态；Windows 入口避开故障 Python 探测和额外的路由器进程，过期会话清理门禁仍需完整的宿主读回。
- “如何发布版本？”等受支持的纯咨询可在答复交付后关闭，讲解对象中的操作名称不会单独产生执行欠账。
- 保留礼貌请求和问句中的验收要求。明确要求继续执行后，若助手仍把可执行工作留到下一步，最多纠正一次；真实的用户等待和外部等待仍可正常结束。
- 复用已登录的隔离 HOME：安装器可迁移经过验证的旧受管 marketplace 暂存源。

### 升级与限制

升级时使用受管安装器，并启动新任务加载新版；旧任务所需缓存继续保留。不改变 schema、公开协议、默认工具审批或发布检查。已有未完成记录不会被追溯认证。

仍包含未发布的 HOL scanner 和手动注册表刷新改动。已消费的 0.13.6、0.13.7 缓存保持原样；0.13.7 未通过 Windows 宿主清理，也未发布。

Windows 原生验收可启用私有 Hook 边界记录，仅包含启动、结束、毫秒耗时和退出码；缺少结束记录代表失败或中断，不能证明完成。

自动答复关闭仅支持有限的中英文表达。未知尾部指令以及无法识别的主题措辞保持待办，其中也可能包括复杂的纯咨询。答复交付不证明内容正确；如果助手已不再提及剩余工作，有界继续执行提醒也不能修复 Codex 的上下文恢复。

### 验证

源码回归覆盖混合请求、操作讲解、未知动作与连接方式、验收约束和压缩恢复。源码、隔离安装、真实信任 Hook、CI 和发布分别核验，当前结果见[验收记录](../LOCAL_ACCEPTANCE.md)。
