# Context Guard 0.16.0 — Unreleased

## English

This is an unpublished source candidate. Public availability is
determined independently by [GitHub Release readback](https://github.com/GreenLv/codex-context-guard/releases).

### Highlights

- Structured credentials no longer reach derived evidence, diagnostics, or shareable exports. Redaction recognizes JSON-serialized credential fields (including escaped-quote forms), URL userinfo, authorization headers, and common token shapes; exports additionally scrub plugin-private absolute paths. The supported domain is documented and bounded.
- Exports never overwrite existing files and never change project directory permissions. A shareable handoff is published exclusively; an existing target keeps its exact bytes and raises an actionable error.
- Private state fails closed when its permission boundary cannot be established: POSIX private modes (`0700`/`0600`) are checked on each use, and on Windows private directories get a read-back-verified protected DACL through native APIs without starting PowerShell on the Hook path.
- SessionEnd saves current state before running resumable cleanup with a short maintenance work budget. Non-blocking locks keep busy sessions from stalling the sweep; the complete installed command retains its three-second host deadline.

### Changes

- Windows startup loads its required system PowerShell modules explicitly; missing Python candidates no longer scan unrelated modules. Existing path, alias and function resolution remains supported, and each lookup restores the caller's module-loading preference. The original 30-second Hook acceptance limit is unchanged.

- Public-tree audits accept an optional private identity list outside the audited tree and apply semantic-boundary matching without embedding personal identities in distributed source. Missing, unreadable or in-tree private input fails closed; existing `--forbid` substring matching is unchanged.
- Windows private-directory readback accepts the first trustee as `LA` only when `ConvertStringSidToSidW` and `EqualSid` prove equality to the complete expected current-user SID. A different local account or machine SID, unresolved alias, or any permission mismatch still fails closed. Windows evidence remains bound to its exact source, artifact and host.
- On Windows, the optional independent answer review reports process startup and cleanup failures instead of returning a successful result when a temporary handle could not be closed. Real Windows behavior remains a separate acceptance gate.
- Known limitation carried over from 0.15.1: words such as `test` in a file path can be counted as extra acceptance items. Multiple such items can activate Context Guard earlier than expected.
- Field-aware evidence sanitization replaces values under documented sensitive key names (matched case- and separator-insensitively), decodes JSON-encoded tool-response strings for structural redaction, and leaves same-shaped ordinary business fields untouched. Raw prompt records keep their authoritative original bytes.
- `context-guard export` publishes exclusively via an atomic link-based create; existing files, directories, and symbolic-link targets are refused with the original bytes intact. Successor packs refuse an existing output directory. The export writer never chmods the project directory; the new export file stays owner-only on POSIX.
- `PrivateBoundaryError` propagates instead of being swallowed; no sensitive data is written through an unverifiable boundary, and error text carries no private content. Windows file-level isolation comes from the verified parent directory plus inheritance; native Windows behavior remains a separate acceptance gate from these source-level checks.
- Session identities are validated and injectively encoded: missing ids are refused rather than merged into one shared directory, non-ASCII bytes escape byte-for-byte (`~xx`) instead of collapsing, over-long ids truncate with a digest suffix, reserved and Windows device names are rejected, case-only sibling collisions are refused, and loading verifies the persisted identity against the event. UUID-shaped ids map exactly as before.
- The direct-command data root follows `CODEX_HOME` (`<home>/context-guard`) when no explicit root is set; the historical default without `CODEX_HOME` is unchanged, and nothing is migrated, merged, or deleted.
- Re-delivered or repeated UserPromptSubmit events stay independent: the hook payload carries no stable per-message identity, so nothing collapses and no input is dropped. A repeated (session, turn, prompt-bytes) shape is recorded only as a bounded, text-free diagnostic observation. Real host re-delivery and any future host message identity remain pending native facts.
- Saved v2 sessions register content-free encoded names for cleanup discovery. Pre-existing directories that have never been registered remain supported, but very small repeated budgets can leave tail entries undiscovered indefinitely; no bounded discovery delay is promised. A missing or corrupted registry falls back to bounded scans with the same limitation.
- Installation uses official Codex marketplace commands with experimental identity `codex-context-guard-v016`. The project installer, staging transactions, archive repair and automatic interpreter binding are removed. Existing bindings remain readable. POSIX can probe fixed global Homebrew, Anaconda and Python.framework locations after PATH fails, without personal-directory search or new bindings; Windows still requires PATH/launcher discovery or an existing valid binding. Actual GUI restart behavior, real old-cache protection, strict second-operation no-op and old-task continuity require native acceptance of the changed bytes.
- Before trusting the new Hooks, finish tasks that depend on the original runtime, then use the official Plugins UI to disable the original `context-guard@codex-context-guard` identity while keeping `context-guard@codex-context-guard-v016` enabled. Do not remove the old plugin or its cache, and do not trust both Hook sets as an upgrade procedure. Old-task continuation is not established.
- `SECURITY.md` states the real support line and current schema/Stop protocol. Schema 13, Stop protocol 5.0.0, the nine Hooks, matchers, and the default business-tool path without execution approval are unchanged; the replay ledger adds no migration.

### Validation

- At `67985d7`, macOS and Windows each completed all eight isolated exact-ZIP portable gates and cleanup; old-cache protection covered synthetic fixtures only. HOL passed for `67985d7`. These observations do not transfer to later source or artifact bytes.
- Check CI/HOL and native evidence separately for each exact commit, artifact and platform in the [acceptance record](../LOCAL_ACCEPTANCE.md). Actual GUI restart, daily old-cache protection, normal user trust and old-task continuation remain unverified.

## 简体中文

本版本为尚未发布的源码候选；公开可用状态由 [GitHub Release 读回](https://github.com/GreenLv/codex-context-guard/releases)单独确定。

### Highlights

- 结构化凭据不再进入派生证据、诊断或可分享导出。脱敏可识别 JSON 序列化的凭据字段（含转义引号形式）、URL userinfo、授权头与常见 token 形态；导出额外抹除插件私有绝对路径。支持域有文档且有界。
- 导出绝不覆盖既有文件，也绝不改动项目目录权限。可分享交接文件以独占方式发布；既有目标保持原字节并得到明确错误。
- 私有状态在权限边界无法建立时失败关闭：POSIX 私有权限（`0700`/`0600`）每次使用时均会检查；Windows 私有目录经原生 API 设置并读回验证受保护 DACL，Hook 路径不启动 PowerShell。
- SessionEnd 先保存当前状态，再以短维护预算执行可续扫清理。非阻塞锁避免繁忙会话拖住扫描；完整安装命令仍须满足三秒宿主时限。

### Changes

- Windows 启动时显式加载所需的内置 PowerShell 模块，查找缺失 Python 候选时不再扫描无关模块。已有路径、别名和函数解析仍受支持，每次查找后均恢复调用方的模块加载偏好。原有 Hook 验收的 30 秒限制不变。

- 公开树审计支持显式传入位于被审树外的私有身份列表，按语义边界匹配，不再在分发源码中内置个人身份。私有输入缺失、不可读或位于树内时失败关闭；既有 `--forbid` 子串匹配语义不变。
- Windows 私有目录读回仅在 `ConvertStringSidToSidW` 与 `EqualSid` 证明第一条 `LA` trustee 等于完整预期当前用户 SID 时接受该别名。不同本机或账户 SID、别名解析失败及任何权限不符仍失败关闭；Windows 证据仅适用于对应的精确源码、制品与宿主。
- Windows 可选独立答案审读在进程启动或清理失败时会报告错误，不再因临时句柄无法关闭而返回成功。真实 Windows 行为仍是独立验收门。
- 沿用自 0.15.1 的已知限制：文件路径中的 `test` 等词语可能被计为额外验收项；多项误识别可能使 Context Guard 提前激活。
- 字段感知的证据清理替换文档化敏感键下的值（忽略大小写与分隔符），对 JSON 编码的工具响应字符串先解码再结构化清理，同形状普通业务字段不受影响。原始 prompt 记录保持权威原始字节。
- `context-guard export` 以原子 link 独占发布；已存在的文件、目录与符号链接目标被拒绝且原字节不变。successor pack 拒绝已存在的输出目录。导出写入器不 chmod 项目目录；新导出文件在 POSIX 上仅属主可读。
- `PrivateBoundaryError` 向上传播而非被吞掉；未通过验证的边界不写入敏感数据，错误文本不含私有内容。Windows 文件级隔离来自已验证父目录加继承；真实 Windows 行为仍是与源码测试分开的原生验收事实。
- 会话身份经过验证并单射编码：缺失 id 被拒绝而不是合并进共享目录；非 ASCII 字节按字节转义而非折叠；超长 id 以摘要后缀截断；保留名与 Windows 设备名被拒绝；仅大小写不同的兄弟碰撞被拒绝；加载时核对持久化身份与事件身份。UUID 形态 id 的映射与之前完全一致。
- 未设置显式数据根时，直接命令的数据根遵循 `CODEX_HOME`（`<home>/context-guard`）；未设置 `CODEX_HOME` 时的历史默认不变；不迁移、不合并、不删除任何数据。
- 重投或重复的 UserPromptSubmit 事件保持独立：hook 负载没有稳定的逐消息身份，因此任何输入都不折叠、不丢弃。重复的 (session, turn, prompt 字节) 形态仅记录为有界、无文本的诊断观察。真实宿主重投与未来宿主消息身份仍是待定原生事实。
- 已保存的 v2 会话登记不含内容的编码名称，供清理发现使用。尚未登记的既有目录仍受支持，但反复使用极小预算可能让尾部目录长期无法被发现；不承诺有界发现延迟。登记表缺失或损坏时回退到有界扫描，并保留相同限制。
- 安装改用 Codex 官方市场命令和实验性身份 `codex-context-guard-v016`。删除项目自有安装器、暂存事务、归档修复和自动解释器绑定；既有绑定仍可读取。POSIX 在 PATH 失败后探测固定的 Homebrew、Anaconda 和 Python.framework 全局位置，不搜索个人目录、不写新绑定；Windows 仍依赖 PATH/launcher 或既有有效绑定。真实 GUI 重启行为、真实旧缓存保护、第二次操作严格 no-op 和旧任务续接需要针对变化后字节的原生验收。
- 信任新版 Hook 前，先完成依赖原运行时的任务，再通过官方 Plugins UI 禁用原 `context-guard@codex-context-guard` 标识，保持 `context-guard@codex-context-guard-v016` 已启用。不要移除旧插件或其缓存，也不要把同时信任两套 Hook 当作升级流程；旧任务续接尚未证明。
- `SECURITY.md` 陈述真实支持线与当前 schema/Stop 协议。Schema 13、Stop 协议 5.0.0、九个 Hook、matcher 与无执行审批的默认业务工具路径不变；重投台账不引入迁移。

### Validation

- 在 `67985d7` 上，macOS 与 Windows 各完成精确 ZIP 的八项隔离 portable 门及 cleanup；旧缓存保护只覆盖合成夹具。`67985d7` 的 HOL 通过。这些观察不转记到后续源码或制品字节。
- 每个精确提交、制品与平台的 CI/HOL 和原生证据分别核对，见[本地验收记录](../LOCAL_ACCEPTANCE.md)。真实 GUI 重启、日常旧缓存保护、正常用户信任与旧任务续接仍未验证。
