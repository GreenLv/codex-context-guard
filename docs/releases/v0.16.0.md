# Context Guard 0.16.0 — Unreleased (source candidate)


## English

### Highlights

- Structured credentials no longer reach derived evidence, diagnostics, or shareable exports. Redaction recognizes JSON-serialized credential fields (including escaped-quote forms), URL userinfo, authorization headers, and common token shapes; exports additionally scrub plugin-private absolute paths. The supported domain is documented and bounded.
- Exports never overwrite existing files and never change project directory permissions. A shareable handoff is published exclusively; an existing target keeps its exact bytes and raises an actionable error.
- Private state fails closed when its permission boundary cannot be established: POSIX modes are set and re-read (`0700`/`0600`), and on Windows private directories get a read-back-verified protected DACL through native APIs without starting PowerShell on the Hook path.
- The installer stages exactly an allowlisted distribution (five runtime roots plus documented license/readme/changelog/security/pyproject files; every other top-level entry is rejected) and runs one installation transaction: same-version drift is refused before any staging or registration change, and a failed install restores the previous staged bytes and registration.
- SessionEnd retention cleanup is bounded inside the three-second host budget: monotonic deadline, non-blocking locks, bounded batches, and resumable partial deletions. Sixteen busy session locks no longer overrun the hook.

### Changes

- Field-aware evidence sanitization replaces values under documented sensitive key names (matched case- and separator-insensitively), decodes JSON-encoded tool-response strings for structural redaction, and leaves same-shaped ordinary business fields untouched. Raw prompt records keep their authoritative original bytes.
- `context-guard export` publishes exclusively via an atomic link-based create; existing files, directories, and symbolic-link targets are refused with the original bytes intact. Successor packs refuse an existing output directory. The export writer never chmods the project directory; the new export file stays owner-only on POSIX.
- `PrivateBoundaryError` propagates instead of being swallowed; no sensitive data is written through an unverifiable boundary, and error text carries no private content. Windows file-level isolation comes from the verified parent directory plus inheritance; native Windows behavior remains a separate acceptance gate from these source-level checks.
- Session identities are validated and injectively encoded: missing ids are refused rather than merged into one shared directory, non-ASCII bytes percent-escape instead of collapsing, over-long ids truncate with a digest suffix, reserved and Windows device names are rejected, case-only sibling collisions are refused, and loading verifies the persisted identity against the event. UUID-shaped ids map exactly as before.
- The direct-command data root follows `CODEX_HOME` (`<home>/context-guard`) when no explicit root is set; the historical default without `CODEX_HOME` is unchanged, and nothing is migrated, merged, or deleted.
- A re-delivered UserPromptSubmit with the exact same session, turn id, and prompt bytes journals one root and derives no second requirement, work unit, wait, or control effect; a bounded text-free replay ledger keeps the collapse visible. Different text or a different turn is always a new input, and payloads without a turn id keep the previous behavior.
- `SECURITY.md` states the real support line and current schema/Stop protocol. Schema 13, Stop protocol 5.0.0, the nine Hooks, matchers, and the default business-tool path without execution approval are unchanged; the replay ledger adds no migration.

### Validation

- Source candidate: complete source gates, isolated install/lifecycle checks, canonical history regression, interleaved performance A/B, and affected native gates for this exact tree are recorded in the [acceptance record](../LOCAL_ACCEPTANCE.md) when complete. Windows DACL/inheritance behavior and real host re-delivery remain native facts, not source-test conclusions.

## 简体中文

### Highlights

- 结构化凭据不再进入派生证据、诊断或可分享导出。脱敏可识别 JSON 序列化的凭据字段（含转义引号形式）、URL userinfo、授权头与常见 token 形态；导出额外抹除插件私有绝对路径。支持域有文档且有界。
- 导出绝不覆盖既有文件，也绝不改动项目目录权限。可分享交接文件以独占方式发布；既有目标保持原字节并得到明确错误。
- 私有状态在权限边界无法建立时失败关闭：POSIX 模式设置后回读校验（`0700`/`0600`）；Windows 私有目录经原生 API 设置并读回验证受保护 DACL，Hook 路径不启动 PowerShell。
- 安装器严格按清单分发（五个运行树根加文档化的 license/readme/changelog/security/pyproject 文件；其他任何顶层条目被拒绝），并执行单一安装事务：同版本漂移在任何暂存/注册变更之前被拒绝；安装失败恢复原暂存字节与注册。
- SessionEnd 保留清理被限制在三秒宿主预算内：单调 deadline、非阻塞锁、有界批次与可续扫的部分删除。16 个繁忙会话锁不再超时。

### Changes

- 字段感知的证据清理替换文档化敏感键下的值（忽略大小写与分隔符），对 JSON 编码的工具响应字符串先解码再结构化清理，同形状普通业务字段不受影响。原始 prompt 记录保持权威原始字节。
- `context-guard export` 以原子 link 独占发布；已存在的文件、目录与符号链接目标被拒绝且原字节不变。successor pack 拒绝已存在的输出目录。导出写入器不 chmod 项目目录；新导出文件在 POSIX 上仅属主可读。
- `PrivateBoundaryError` 向上传播而非被吞掉；未通过验证的边界不写入敏感数据，错误文本不含私有内容。Windows 文件级隔离来自已验证父目录加继承；真实 Windows 行为仍是与源码测试分开的原生验收事实。
- 会话身份经过验证并注入式编码：缺失 id 被拒绝而不是合并进共享目录；非 ASCII 字节按字节转义而非折叠；超长 id 以摘要后缀截断；保留名与 Windows 设备名被拒绝；仅大小写不同的兄弟碰撞被拒绝；加载时核对持久化身份与事件身份。UUID 形态 id 的映射与之前完全一致。
- 未设置显式数据根时，直接命令的数据根遵循 `CODEX_HOME`（`<home>/context-guard`）；未设置 `CODEX_HOME` 时的历史默认不变；不迁移、不合并、不删除任何数据。
- 同一 session、turn id 与 prompt 字节完全一致的 UserPromptSubmit 重投只记录一个 root，不派生第二个需求、工作单元、等待或控制效果；有界无文本的重投台账保持折叠可见。不同文本或不同 turn 永远是新输入；无 turn id 的负载保持原行为。
- `SECURITY.md` 陈述真实支持线与当前 schema/Stop 协议。Schema 13、Stop 协议 5.0.0、九个 Hook、matcher 与无执行审批的默认业务工具路径不变；重投台账不引入迁移。

### Validation

- 源码候选：本候选的完整源码门、隔离安装/生命周期检查、canonical 历史回归、交错性能 A/B 与受影响原生门在完成后记录于[本地验收记录](../LOCAL_ACCEPTANCE.md)。Windows DACL/继承行为与真实宿主重投是独立原生事实，不由源码测试代替。
