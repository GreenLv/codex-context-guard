# Context Guard 0.17.0 — Unreleased source candidate

This line is not published. Every claim below is the candidate contract; the
release gate, full-matrix CI, native macOS/Windows acceptance, installed
artifacts and the identity switch are separate pending evidence for the
independent review stage.

## English

### Highlights

- Planning-only requests no longer inherit a file-modification obligation. Another actor's completed work, attributed advice, stated future intent and bare verb negation are interpreted through one clause-action rule (clause derivation 1.1.0); only a current-turn directive stamps the enforced contract or authorizes an action category. Delegation, mixed planning-plus-directive prompts and plan-reference prefixes keep their real obligations. Intake, evidence, Stop gating and cold recovery follow the same derivation.
- The Desktop `aggregated_output` terminal result is accepted through one authoritative-output rule beside the legacy `stdout` field: an exactly equal pair is accepted, a conflicting pair stays rejected, and identity, working-directory, status and exit-code bindings are unchanged. Success and failure exits are both recognized again on the current Desktop host.
- An unrelated oversized transcript row no longer disables terminal evidence for later normal commands. A row above the line limit is skipped only when a complete, bounded strict JSON parse proves its single outer type can never carry the terminal candidate; escaped or duplicate member names, malformed values, any oversized `event_msg` and unknown types keep the whole snapshot unavailable. Ordinary rows follow the same strict reading. No event identifier is guessed from oversized rows; limits are not raised.
- Session retention cleanup returns under a new versioned contract. `cleanup` previews by default; deletion needs an explicitly enabled policy (30-day minimum age, 7-day quarantine, clamped, purge optional) and an apply bound to an exact manifest. Quarantine keeps a restore command; purge runs only after the grace period with bounded resume and expiring tombstones. Active, resumable, unfinished, busy-locked, partial, legacy, linked and out-of-scope objects are protected with a named reason. Restore moves an object back only after proving it complete; purge waits for the original session's lifecycle lock and is never undone into a partial restore. SessionEnd still runs no sweep. All 30 retired retention test nodes are individually mapped in `tests/retention_restoration_mapping.json`.

### Compatibility and upgrade

- The marketplace identity moves from the experimental `codex-context-guard-v016` to the stable `codex-context-guard`. Registering the stable marketplace and installing from it are official same-identity operations: they may remove the old experimental cache, and keeping a cache never proves an old session loads it. Finish tasks that depend on the published 0.16.1 runtime first or use a separately configured HOME. See the [stable identity contract](../../tools/validation/STABLE_MARKETPLACE_IDENTITY.md).
- Existing sessions, registries, cursors, pending chunks and partial markers are preserved. A policy object is never created automatically; an upgraded installation stays preview-only until the user explicitly enables a policy. No automatic scheduler is registered by installation.

### Validation

- Two review rounds: the first candidate failed with 11 reproducible
  violations; after repair R1 the second review found 12 adjacent
  counterexamples in seven families. Repair R2 closes each family by its
  invariant. The library record that had been deleted and re-added under
  the same ID keeps its original bytes under a hash-bound rejected-intake
  record; the corrected facts carry a new ID and the pin is re-frozen.
- macOS source evidence only: the original incident oracles (3 planning-scope assertions and 3 terminal-evidence assertions failing on the 0.16.1 baseline) pass on this candidate together with their controls, plus new family regressions, the restored retention suite, and the migrated disabled-state controls. Full-matrix CI, native retention acceptance, performance contracts against the published baseline, the canonical historical-library gate, and installed-artifact checks are separate pending gates. Nothing here is released evidence.

## 简体中文

### 亮点

- 只规划内容的请求不再继承文件修改义务。他人的已完成动作、被引用的建议、声明的未来意图和对动作动词的裸否定统一由同一条子句动作规则解释（子句派生版本 1.1.0）；只有本轮本人的指令才会给强制合同盖章或授权动作类别。委托、规划加当前实际修改的混合请求、计划引用前缀仍然保留真实义务。入账、证据、Stop 门与冷恢复走同一派生。
- 当前 Desktop 的 `aggregated_output` 终端结果通过一条权威输出规则与旧 `stdout` 字段一同接入：两者完全相等时接受，冲突时继续拒绝；身份、工作目录、状态与退出码绑定不变。成功与失败退出在当前 Desktop 宿主上都能重新被识别。
- 无关超大历史输出不再使后续正常命令的终端证据失效。超过行限的记录只有在完整、有界的严格 JSON 解析证明其唯一外层类型不可能承载终端候选时才被跳过；转义或重复的成员名、非法取值、任何超大 `event_msg` 与未知类型都让整个快照保持不可用。普通大小的记录使用同一严格解读。不会从超大行猜测事件标识；没有提高任何限额。
- 会话保留清理在新版本化合同下恢复。`cleanup` 默认只预览；删除需要显式启用的策略（默认结束 30 天后、隔离 7 天，均有限幅，永久回收可选）和绑定精确清单的 apply。隔离保留恢复命令；永久回收只在宽限期后进行，带有限恢复与到期退役的墓碑记录。活动、可恢复、未完成、锁占用、部分删除、旧版本、链接与范围外对象都会以明确原因被保护。恢复只在证明对象完整后才搬回；永久回收会等待原会话的生命周期锁，开始后不会再被当作可恢复的部分对象。SessionEnd 仍不做清扫。30 个退役保留测试节点在 `tests/retention_restoration_mapping.json` 中逐项映射。

### 兼容与升级

- 市场身份从实验性 `codex-context-guard-v016` 切换到稳定 `codex-context-guard`。在稳定身份下注册市场并安装属于官方同身份操作：可能移除旧实验缓存，保留缓存也不能证明旧会话会加载它。请先完成依赖已发布 0.16.1 运行时的任务，或使用另行配置的 HOME。见[稳定身份合同](../../tools/validation/STABLE_MARKETPLACE_IDENTITY.md)。
- 既有会话、注册表、游标、pending 分块和部分删除标记全部保留。策略对象永远不会自动创建；升级后的安装保持只预览，直到用户显式启用策略。安装不会注册任何自动调度器。

### 验证

- 两轮复核：首个候选有 11 个可复现违约；返修 R1 后第二轮复核又在七个问题族中发现 12 条相邻反例。返修 R2 按各族不变量封闭。曾被删除后以同一 ID 重新加入的库记录保留原始字节，并以绑定哈希的拒收记录登记；更正后的事实使用新 ID，pin 已重冻。
- 仅有 macOS 源码证据：0.16.1 基线上失败的 3 条规划范围断言与 3 条终端证据断言在本候选上连同对照全部转正，另有新的问题族回归、恢复后的保留套件与迁移后的禁用态控制。全矩阵 CI、原生保留验收、对照已发布基线的性能合同、历史错误库门与安装制品检查是独立的待办门。本页任何内容都不是发布证据。
