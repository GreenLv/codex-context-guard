# 下个版本：回答交付与复杂请求的语义覆盖

状态：待完善的下版问题与设计记录，2026-09-14。本页不表示运行时已修复，也不指定发布版本。代码观察基线为已发布 0.13.9 之后仅含文档改动的提交 1105b2f8180133bd5b1c8836212c31f79e8a855b。

## 背景与既有分析

[SEMANTIC_COMPATIBILITY.md](SEMANTIC_COMPATIBILITY.md) 规定共享语义、冻结镜像和各宿主的证据边界，并不宣称 DSH 与 Codex 全部功能一致。此前分析还记录在 context-guard-effectiveness 仓库的 docs/SEMANTIC_BOUNDARIES.md：按原文跨度拆分义务，按类型匹配证据，未知部分保持可解释；模型可协助提出解析候选，但不能成为授权、完整性或完成的最终权威。本页延续该方向。

0.13.2 已引入回答交付记录；0.13.9 扩展命令式讲解请求，并保护解释后的执行尾句。但 `_reply_only_request_shape` 仍使用有限主题与句型的整句匹配。它对接受的语法保留整句边界，无法保证所有自然表达都能关闭。

## 本轮观察

在 0.13.9 的合成 Hook 测试中，简短的“讲解项目内容与核心逻辑”一类请求可进入 answered；在同类请求后加入流程图与理解目的的附句，或使用长复合提问，可能仍留在 pending。原始完整对话保留在私有材料中，本仓库不复制用户原文、会话身份或安装路径。

定位：scripts/context_guard.py 的 `_information_delivery_item` 先检查规范约束和未解析资产，再调用 `_reply_only_request_shape`；不匹配就不进入回答交付关闭路径。该行为与先前解决的“只识别解释开头，吞掉后续执行尾句”互为风险：允许任意后缀会误关闭执行义务，词表过窄又会误保留已交付问答。

已有 tests/test_information_delivery_closure.py 的 25 个测试在上述源码上通过；额外完整请求重放仍观察到 pending。因此通过现有测试不能证明复杂问答的语义覆盖。该证据属于合成 Hook 重放，不是 Codex 实机无限续跑或 Windows 原生复现。

## 与 DSH 事故的区别

DSH Completion Guard 0.5.2 另有 prepare 输出包含 undefined 的实现缺陷，已在其所属仓库作局部修复。DSH 的 Git 取证失败调用还缺少计划工具清单或前置调用引用，不能由此断言适配器不可达。这些 TypeScript 工具边界不是 Codex Python Hook 的同一实现。

Codex 普通执行路径在 0.13.2/0.13.3 后不再依赖 Guard 重建授权链来拦截普通提交或推送。回答交付覆盖不足仍可能造成恢复中的未决残留，但不能据此重新引入普通执行否决、要求用户反复授权，或把 DSH/Windows 的证据升级为 Codex/Windows 原生事实。

## 下版工作项（均待实现与验收）

| 工作项 | 目标 | 不能越过的边界 |
| --- | --- | --- |
| 原文跨度覆盖 | 信息、执行、约束及未知部分各有稳定来源 | 未覆盖尾句不得被丢弃，模型摘要不替代原文 |
| 回答交付记录 | 绑定当前根输入、原生 turn、最终回答和已交付范围 | 交付不证明正确、充分或执行完成 |
| 复合请求 | 回答子项与执行子项分别验收 | 回答不能关闭修改、测试、发布等义务 |
| 可解释不确定状态 | 显示解析缺口，避免重复要求用户改写 | 不能伪造完成、等待资格或执行授权 |
| 延迟与恢复 | compact/resume 保留有效交付及未完执行 | 子代理、过期回答和摘要不能满足新问题 |
| 升级与共享语义 | 明确迁移、旧状态和各宿主适配边界 | 不改写冻结 fixture，不互认 native 证据 |

先以观察方式运行跨度解析与义务分解，再用独立标注对比现有实现。模型结构化建议可以扩大候选覆盖，但不能单独认证自己的回答；未知表达也不能自动升级成执行权限。应同时衡量误关闭、误保留、额外轮次和延迟，不能只比较总通过率。

## 待补回归与验收

1. 简短与复杂信息请求：增加附图、目的、复合疑问、代词、条件及中英文混合。用公开合成改写，不提交原始会话。
2. 对照同一前缀后分别添加解释附句、明确执行、未知执行尾句；不能只修正正例而漏掉执行保护。
3. 覆盖引用/代码块、否定、跨 turn 延迟回复、子代理回复、中止、compact/resume 与旧状态恢复。
4. 输出应区分 answered、执行已认证、未知和待用户/外部事件；需明确如何作用于父项范围与 Stop 预算。
5. 若行为进入共享语义，依 [SEMANTIC_COMPATIBILITY.md](SEMANTIC_COMPATIBILITY.md) 先形成中立合成用例，再更新 DSH 的精确镜像与原生验证。

本轮只记录问题和待办，不修改 Codex 运行时、缓存、Hook、版本或共享 fixture。下一次实施应先冻结此处的边界与反例，再选择协议和迁移方案；当前文档可继续补充实际观察与验收结果。
