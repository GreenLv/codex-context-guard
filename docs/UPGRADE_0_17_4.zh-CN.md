# 升级到 Context Guard 0.17.4

[English](UPGRADE_0_17_4.md) · [发布附件](https://github.com/GreenLv/codex-context-guard/releases/tag/v0.17.4)

0.17.4 让日常升级工具在暂停后更容易接续，Hook 和清理行为沿用 0.17.3。操作工具从 `v0.17.4` 标签对应的源码仓库取得，不包含在发行 ZIP 中，也不安装到插件缓存。

## 准备稳定入口升级

以下流程适用于已启用的 0.17.3 稳定入口 `context-guard@codex-context-guard`。如果使用更早版本或其他入口，请先按 [0.17.3 升级指南](UPGRADE_0_17_3.zh-CN.md)及其中链接的更早指南处理，包括清理设置说明。如果希望插件保持禁用，请保持原状态，待决定启用时再执行此流程。

保留上一版经核验的 ZIP 和市场来源目录。下载 `context-guard-0.17.4.zip`，核对发布页公布的 SHA-256，解压到长期保留的目录作为新市场来源。操作工具另从 `v0.17.4` 标签对应的源码仓库取得。

按[日常升级工具说明](https://github.com/GreenLv/codex-context-guard/blob/v0.17.4/tools/validation/DAILY_UPGRADE.md)填写私有计划，明确发行包目录、CLI 和实际 Desktop 可执行文件。退出 Desktop 前先完成命令预检。计划与批次结果保存在源码仓库和日用配置目录以外。

## 切换与核验

先完成或安全交接仍需旧 Hook 的任务。官方市场操作可能删除旧缓存，替换已有安装前必须确认 Desktop 已退出。从外部终端启动接续命令；使用 `--resume --wait` 时，工具可以在限定时间内等待 Desktop 退出，再继续安装；`--wait-minutes` 用于设置等待上限。等待结束时若 Desktop 尚未退出，按工具提示处理。无需切换时，直接继续核验，不要重复安装。

重新打开客户端，在 CLI 的 `/hooks` 界面，或 Desktop 的 **Review hooks**（审核 Hook）／**Settings > Hooks**（设置中的 Hook 页）审核来自新安装路径的九个 Hook，再用同一计划和批次继续核验。通过表示官方安装记录、发行文件和新客户端观察到的 Hook 一致；它不能证明已有 Desktop 进程内存中加载的版本，请在下一次 Desktop 任务中确认。

批次中断时保留记录，按工具的恢复提示继续，不要从头重复安装。如果安装尚未开始，且只有同一路径下可执行文件的字节发生变化，受控重绑定会先核验宿主身份和签名来源，再生成新的准备记录。其他输入变化、宿主路径变化或已经开始安装的批次，需要按工具提示恢复，或重新评审并创建新批次。

升级保留稳定入口和现有数据根。禁用策略、自定义保留期、仅隔离设置和持久关闭记录继续生效。无策略时，会话结束超过 30 天后才可隔离，隔离至少 7 天后由后续自动维护永久删除。检查、关闭和恢复命令见[会话存储](SESSION_STORAGE.md)。

保留上一版核验过的 ZIP、源码和本批结果以便恢复。降级需另行使用官方安装操作，不要向已消费缓存手动复制文件。
