# Semantic Compatibility

This repository is the canonical owner of the shared Context Guard protocol
semantics that `dsh-completion-guard` (DSH) adapts onto its native host. The
two products keep separate runtimes, persistence, lifecycle, and scheduling;
what they share is a testable semantic contract, tracked by a machine-readable
delta ledger and portable conformance fixtures. This document describes the
shared assets and their authority boundaries. It does not claim full feature
parity between the products.

## Shared assets

```text
docs/upstream-deltas.json
tests/fixtures/conformance/context_guard_semantics_v1.json
tests/fixtures/conformance/context_guard_semantics_v1.schema.json
tests/fixtures/conformance/digest_v3/cases.json
tests/fixtures/conformance/digest_v3/expected.json
scripts/reference_digest_encoder.py
```

Authority rules:

- The portable conformance fixture and the digest v3 fixture are canonical in
  this repository. DSH holds byte mirrors pinned to the exact file SHA-256
  values recorded in its `tests/fixtures/conformance/UPSTREAM_PIN.json`.
- Existing `tests/fixtures/incidents/public_incidents.json` stays the Codex
  incident corpus. It is not a cross-platform protocol file.
- New protocol cases discovered on the DSH side are turned into
  platform-neutral fixture cases here first; host-specific expectations never
  enter the shared fixture.
- Cross-language consistency compares the committed raw bytes (SHA-256) of
  fixture files, never re-serialized JSON.

## Digest v3 gate

`certificate`, `boundary`, and evidence manifests bind to versioned canonical
digests. The derivation contract is frozen as digest version 3: a typed token
value language (`b:`/`i:`/`s:`/`e:`/`x:`), a length-prefixed `field()` encoding
with an explicit presence byte, canonical set/map/bindings collections that
sort by semantic key bytes and fail closed on duplicates, and per-manifest
closed field allowlists with domain separators
(`ccg.sessionRefDigest.v3`, `ccg.hostLockDigest.v3`, `ccg.evidenceFact.v3`,
`ccg.evidenceSha256.v3`, `ccg.binding.v3`, `ccg.bindingDigest.v3`,
`ccg.predParams.v3`, `ccg.certificationDigest.v3`, `ccg.locator.v1`).

The typed token domains are frozen with the contract: `i:` tokens carry
decimal integers without redundant zeros inside the safe-integer domain
−(2^53−1)…2^53−1. At the decoded JSON/native input boundary, any finite
safe number that is numerically integral is normalized to that token form, so
`1`, `1.0`, and `1e0` all encode as `i:1` (and negative zero encodes as
`i:0`); non-integral and non-finite numbers fail closed. The reference encoder,
the DSH mirror, and the shared conformance schema enforce that same numeric
domain and bounds. String-ID fields (binding evidence IDs), collection entries
(`operations`/`executables`/`subjects`/`supportedGoalVersions`), and the
certificate version strings are string-only domains. Any change to the
algorithm, separators, typed token language, or these domains is a new digest
version and must update both implementations, the fixtures, this document,
and the shared schema together.

The frozen gate contract:

- `tests/fixtures/conformance/digest_v3/cases.json` carries 29 machine-readable
  vector inputs. Golden values are never hand-copied;
  `expected.json` is generated by the reference encoder.
- `scripts/reference_digest_encoder.py` is the canonical encoder. The gate
  command is:

  ```shell
  python scripts/reference_digest_encoder.py --check tests/fixtures/conformance/digest_v3/cases.json
  ```

  It recomputes every vector and exits non-zero on any difference.
- DSH byte-mirrors both fixture files and runs its own runner against them;
  the mirror check must agree with this repository's `expected.json`.
- The vectors cover session identity (4), host lock (4), the certificate chain
  (evidence fact, evidence set, predicate parameters, binding records,
  binding digest, certification digest), a full pull state-closure chain,
  Unicode (astral scalar, NFC vs NFD without normalization), and opaque
  locators (same reason, different locator, no identity collapse).

Fail-closed edges pinned by regression tests include: lone surrogates are
rejected before hashing; digest inputs are not Unicode-normalized (NFC and NFD
differ); integers outside the frozen safe-integer domain are rejected;
dynamic key names must match `^[a-z0-9_]{1,64}$` (camelCase is
rejected before hashing); encoded field names are length-prefixed so hostile
names cannot collide with concatenated short fields, and the manifest grammar
layer independently rejects them; values are capped at 4096 bytes and
predicate parameter payloads at 4096 canonical bytes (4096/4097 boundary
tested); duplicate set members, map keys, and `(item, semanticAction)` binding
pairs are rejected; evidence facts enforce the role matrix (resolution/effect
carry `res:` only, state carries `res:` and `obs:`), and bindings close against
byte-identical `resolvedTarget` rows across all three roles with pairwise
disjoint `obs` key sets and evidence IDs that pair with the facts playing
those roles.

## Portable conformance fixture

`context_guard_semantics_v1.json` holds platform-neutral cases built from the
event vocabulary `root_message`, `delegated_message`, `tool_result`,
`checkpoint_request`, `boundary_request`, `completion_request`, `compact`,
`resume`, and `goal_change`, with expectations limited to `completed`,
`completion_allowed`, `force_continue`, `pending_preserved`, `boundary`,
`integrity`, and `reason_codes`. All content is synthetic; the hygiene test
rejects absolute paths, credentials, tokens, and session locators.

The first batch covers: root versus delegated/internal/goal/plugin authority;
contract capture with conversational filtering, mixed clauses, supersession,
and clear-pending; success/failure/unknown/durability-unknown evidence;
method/operation/subject/surface binding; stale revision, stale epoch, stale
Goal ref, cross-host-lock replay, and forged certificate rejections; Stop
Protocol 2.0 text metamorphic cases; `user_wait`/`external_wait`/`deferred`
qualification; compaction and resume recovery dedup; private metadata
containment and bounded diagnostics; Unicode and path forms; authoritative
instructions versus pasted reference reports; explicit adoption versus
material self-promotion; minimal evidence certification with fail-closed
mixed-evidence rejection; evidence summaries that distinguish actions without
leaking command bodies; boundary disposition qualification; boundary
append/flush/sync/disarm/readback failure windows; minimal effect plus
independent state readback for the stateful action set; Guard-owned Goal
complete gating versus trusted bypass integrity detection; retention and
control-chain observability; and the real-session regressions (a pasted
report must not explode the contract; a clean unittest must not certify
install/pull/commit/push and mixed evidence must name the offending IDs).

Cases whose runtime behavior is still versioned future work stay listed with
their expected outcome; the delta ledger records per-capability
implementation status. A capability that a platform cannot support is marked
`not-applicable` or `deferred` in the ledger, never silently `pass`.

## Layered alignment scope

- **Layer A (completion semantics).** Inside the Guard protocol and the model
  tool paths it guards, the current contract plus current evidence is the only
  completion authority; assistant prose is diagnostic only. Without
  structured control the turn yields safely and pending work is preserved.
  Wait/deferred dispositions exist only with deterministic qualification.
- **Layer B (full proof semantics).** Subject readback, scope coverage, and
  state verification as versioned, hash-bound, replayable proof manifests;
  multimodal proof stays `deferred` until the host exposes stable structured
  asset interfaces.
- **Layer C (product capability assessment).** Subagent provenance, Goal/Plan
  mirroring, handoff, and execution protocol coverage are assessed per host;
  file or module counts are not alignment evidence.

Completion of Layer A may only be claimed for the guarded paths; trusted
in-process host bypasses are detectable as integrity violations, not
prevented, until a host provides a pre-commit invariant.

## Validation boundaries

- Passing the digest fixture gate or unit tests is deterministic-test
  evidence only. It does not substitute for native platform acceptance,
  installed lifecycle checks, tag or release identity readback, or CI.
- The delta ledger (`docs/upstream-deltas.json`) separates source facts,
  plan status, implementation status, deterministic tests, native platform
  acceptance, and release readback. Keep all six aligned when a capability
  moves.
- Evidence statements in this document name their boundary and are limited to
  this repository's public tree.
