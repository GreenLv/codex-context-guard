# Context Guard 共同核心合同：DSH 0.7.0 / Codex 0.14.0

规划合同版本：2.0-plan.2，2026-09-18。本文规定新版本的职责、状态与接受条件，不声称已有实现通过，也不是执行、安装或发布授权。产品版本、协议版本与本文版本独立。

## 1. 权威源与适用范围

本轮两份开发计划引用本文的逐字相同副本；协调者维护规划合同，禁止任一产品自行改变语义。产品落地时，Codex Context Guard 仓库是共享规范、JSON schema、reference projection 和中立 fixture 的唯一权威源。先在该仓库完成 P0，再由 DSH 按确切 commit、路径及 SHA-256 镜像；不得把 DSH 单边 candidate 称为共享标准。两份规划副本也必须做字节相等检查。上游的公共文件不得依赖私人协调仓库或本机路径。

本文的 AC01–AC12 补充并约束既有 C01–C12。旧版记录保留历史效力；0.6.3 的文本执行资格与收窄表达合同不得成为 0.7.0 默认路径。新合同不是保证任意自然语言可被确定性证明，而是规定不能从解析不确定性产生执行权限、错误完成或额外普通审批。

只对齐共同语义和可观察行为：要求、来源、工作单元、回答、证据、完成、普通执行职责和显式发布规则。Codex Hook/cache、DSH Session/Goal/Web/Headless、调度和安装分别属于宿主；事件名称、工具名称、消息措辞和制品 hash 不要求相同。

## 2. AC01：三个责任边界

| 路径 | 负责执行与权限的一方 | Guard 必须做什么 | Guard 不得做什么 |
| --- | --- | --- | --- |
| standard 普通任务 | 执行助手依据真实用户请求、仓库规则和宿主审批；宿主执行工具 | 保存完整要求/约束，观察真实工具结果，恢复上下文，核验完成事实 | 用文本分类器签发普通执行资格；要求先走 prepare/action/rebind 才能编辑、测试、提交、推送 |
| strict 普通任务 | 同 standard | 对用户明确要求的视觉/完整范围等 proof 保持强制核验 | 把证明义务转换成普通工具前置审批或重复用户授权 |
| 显式 release 契约 | 助手仍负责用户授权；宿主仍负责平台审批；Guard 只强制已采用契约 | 精确身份、readiness、单次票据、效果前检查、消费与可信回读 | 从安装、关键词、Skill 或普通 push 自动采用契约；建议或认证绕过已采用契约；把不可拦截的宿主通道说成已被阻止 |

“没有 Guard 否决”不是授权；模型仍必须遵守原始约束。Guard 的解释标签是理解候选或证明范围，不是安全沙箱。host-lock/完整性失败使 Guard 的认证或受控执行 unavailable；普通宿主工具权限仍由宿主决定，不能因插件不可用把整个宿主变成不可操作。

## 3. AC02：DSH 自有执行器的迁移决策

0.7.0 默认路径停止提供 Guard 自有普通 mutation 执行能力。`context_guard_action` 和 evidence 工具内的 effect 执行分支不得仅通过改名、policy 条件或“可选”标记继续承担普通 Git/安装/修改授权；迁移到宿主普通工具执行，Guard 只消费可信观察。prepare 如保留，只给事实/证据诊断，不能给出普通动作的 authorized/granted 结论。

兼容入口可以返回结构化 `ordinary_execution_moved_to_host`，说明使用宿主普通工具，**不能执行效果**，不能要求用户重写或再批准。新任务的工具描述、恢复提示、Skill、README、测试都不得引导普通操作回到这条旧链。旧记录中的 `ExecutionQualification` 可保留用于历史解码，不参与新普通执行、目标选择或当前完成推断。

受控发布可以继续使用专用 action 实现，但只能由已显式采用、覆盖该操作的 release 契约进入；运行时必须重新检查完整契约，不信任调用方传入的模式。停用旧普通执行器不等于删除身份/producer/前置状态校验：这些检查转归证明验证器或受控发布路径。旧工具名、旧会话、模型误调用和 wrapper 均须有无副作用测试。

Codex 0.14.0 保持既有普通工具边界，不为了接口对称新增 DSH action/prepare，也不将新解释内核接回普通 PreToolUse 审批。

## 4. AC03：来源、解释与完整覆盖

根输入/资产身份不可变；语义记录使用 UTF-8 字节半开区间、原文 hash、unit、revision、来源种类及覆盖余项。保留正向要求、禁止、条件、信息与未知范围，引用/工具/子代理/压缩摘要不能增加用户权限。

解释可以由现有助手提出结构化候选，也可由受支持的确定性规则生成。验证器检查来源、覆盖、类型结构、约束、目标关联及修订；模型自报“这是指令/全部覆盖”不是事实证明。未知残余保持可见，不得从闭包丢弃。没有可靠语义依据时不签发信息关闭或执行完成，但这不阻塞普通工具或诚实结束。

不扩张词表来证明开放自然语言的授权；不要求用户改分号、写插件 DSL 或固定重述模板。固定的必修中文/英文常用表达须正常处理，不能通过全部 unresolved 来取得安全结果。真实歧义才请求最小业务澄清；解析器缺能力、证据不足和缺用户权限分别诊断。不得增加插件自己调用外部模型的运行时依赖；Codex 保持标准库边界。

## 5. AC04：状态维度与闭包

P0 必须把下列概念映射为版本化 schema，禁止使用一个 `authorized/completed` 布尔值混合它们：

| 维度 | 最少需要表达的事实 |
| --- | --- |
| 来源/解释 | 原始来源、candidate interpretation、已验证结构、unknown residue |
| 回答交付 | not_observed / delivered，绑定正确 unit/turn/最终回答/范围；不表示答案正确 |
| 业务效果 | not_observed / success / partial / failure / unknown，绑定真实工具和目标 |
| 证明资格 | supported / unavailable / insufficient / satisfied / invalidated |
| 闭包 | 当前 unit + 必需后代的未满足要求、持续约束、等待、legacy review；历史兄弟任务不混入 |
| Stop 决定 | ordinary_end / bounded_correction / typed_wait；与证书签发分开 |
| 发布 | 未采用 / 已采用 / 已保留 / 已消费 / 结果未知，按已有 release 状态机扩展 |

信息 delivered 仅覆盖可信最终回答的对应信息项，不覆盖混合执行/资产/proof。执行 verified 需要匹配的证据，final、工具零退出、别项完成或解释分类本身均不充分。父项只有适用必需后代满足才能完整认证。禁止项持续有效，不作为永远待执行的动作计数。

## 6. AC05：普通结束、纠正与 Goal

ordinary_end 可以保持未认证状态；不得把所有 pending/unresolved 自动变成阻止结束的债务。等待或无可执行证据时静默保留；不能通过伪造 typed boundary 才让用户得到答复。恢复时展示真实剩余要求和能力缺口，不制造重复工作。

纠正仅用于有明确可追溯依据的提前完成/漏项或违反显式 proof 的完成声明；每 turn 最多一次可见纠正，进展指纹不变不得自旋。不以动词出现、词表推断、历史 broad resume 或 `ExecutionQualification` 证明当前存在必须自动执行的工作。纠正自身也不产生执行权限。纠正预算用完后保留未认证结论，不伪造通过。

### AC05.1：继续提示所需的当前动作依据

2026-09-18 的 Codex 0.13.9 误报表明，仅禁止“generic 推为 authorized”还不足以指导替换实现。`remaining_action_facts → _action_authorization → resumed_actionable_work → Stop` 可把后续收益观察补成当前动作，再把简短修复指令提升为持续执行要求。该事实只在 Codex macOS 观察与隔离 Hook 回放中成立；DSH 必须实现同一防护，不据此宣称 DSH 已复现。

P0 必须为“提示助手继续执行”冻结可追溯的动作依据及其校验规则，至少关联：当前 unit/revision、根要求及其采用范围、具体动作/对象或仍有效要求的必要子步骤、未满足的完成谓词、负责方、条件与输入是否就绪、来源跨度/事件和截至当前 turn 的判断水位。子步骤不要求用户逐项枚举，但必须解释其与已授权目标的必要关系；仅凭模型补写 owner、类别或 `authorized=true` 不成立。该依据用于 Stop 诊断，不是普通工具权限票据；资料不足保留未决并允许诚实结束，不新增执行前审批。

- 分开本轮具体剩余动作、证据/能力不足、未来效果评估、范围外建议、真实用户/外部等待和已完成状态。含动作词的收益/稳定性限制说明不能单独创建当前待办；同句和跨句的完成片段不得借旁边的未来标记变为未完成。
- `explicit_user_persistence` 只来自可信根要求中真实的持续执行指令；`resume_with_actionable_work` 必须同时有当前恢复指令和上述具体动作依据。两类独立存储、独立原因码，禁止用 OR 写回“用户要求持续执行”；默认未知类别/不明确范围不能补成 authorized。
- 跨轮持续、暂停、恢复与取消必须记录真实根来源跨度及水位，绑定该时点当前业务要求的 ID、版本、来源、对象和范围。纯信息插问不遮蔽既有持续范围，后续新任务不能继承旧控制；暂停保留未完成要求但暂不提示当前动作，明确恢复只解除对应暂停，取消只移除所指业务范围。普通控制不得撤销禁止项、显式 proof、已采用 Goal 或 release 合同，也不得回写较早 Stop。旧状态缺少范围绑定时保留未决，不从历史文本重建可信控制。
- `registered_external_operation` 需要实际关联的外部操作或可信生命周期事实；“未提交”“以后观察”本身不能创建已登记等待。无法确认等待时可以普通结束且未认证，不能捏造 boundary。保留原始用户明确等待约束，并与外部操作登记分开。
- 只使用截至该次 Stop 的要求与事实；之后新增“安装/提交/推送”的授权不能回填早先决定。同一结果换掉未来观察措辞不应改变当前动作集合。若用户确实要求立即设计/运行效果评估，或当前测试明确未跑且具备输入，则必须识别该具体剩余动作，不能用“观察类”白名单一概放过。

继续提示要求“有当前动作依据”；错误整项完成/显式 proof 的纠正沿用 AC05 独立判据，不能以没有可执行动作放过错误认证。纠正总预算、无进展规则及恢复范围保持不变。

宿主 Goal 的 `complete` 是完成状态变更，不能与普通聊天结束混同：显式采用的 Guard/Goal 完成合同仍需全部必需证据。无法认证时拒绝 Guard 介导的 Goal 完成并说明缺口，宿主保持实际未完成状态；不自动暂停/重启/改标 blocked，不借“普通结束”宣布 Goal 成功。没有采用这种合同的宿主 Goal 不能由插件擅自接管。DSH 必须核验现有 Goal 接线的采用条件和覆盖；未覆盖旁路公开声明，不伪造全局保障。

## 7. AC06：普通工具证据的进入路径

使用宿主实际提供的工具调用/结果与持久化事件，输出中立 fact：真实 call/operation lineage、producer、subject、时间/水位、结果、可证明的 predicate、原始材料摘要和能力边界。模型给出的 call ID、文本声明或自造 receipt 不能创建可信事实。

宿主适配器负责 observation → fact，核心负责 fact → predicate satisfaction。必须支持已有标准普通工具的有界成功路径：文件改动+回读、测试运行、Git commit/push 的精确 readback，以及只做解释的可信交付。按本次任务所需 predicate 收证据；不是所有普通工具都必须新写认证适配器。

- shell 退出码只证明进程结果。复合命令部分失败、循环/catch 掩盖失败、引用报错文本分别建正反例；不能整段 success 关闭全部子项。
- action-event（本次发生某操作）与 state-outcome（现在满足某状态）必须区分；现状不能反推历史动作或缺失前态。普通工具已有可信历史只要满足 predicate 可接入，不强迫重执行以制造 Guard producer。
- 缺适配器返回 capability_unavailable，缺足够事实返回 evidence_insufficient；都不说“请再授权/改成另一动作”。允许诚实普通交付，不能签发超出证据的证书。
- 视觉、指定资产、完整集合和明确 proof 要求保留原强度。没有可观察生产者时显式记录缺口，不把普通路径迁移当作放宽证明。

## 8. AC07：目标身份与权限来源分离

分别记录根约束、助手在已允许范围内的实现选择、宿主可信选择、执行解析、实际观察身份。cwd、最近工具路径和模型 selector 不自动成为根权限；普通选择也不必被伪装成根用户逐字段指定。

跨仓库“提交并推送”复用当前工作单元内唯一且有来源的合法工作对象；显式目标冲突不得替换，多候选才消歧。该判断用于约束保留和证据匹配，不重建普通操作前置审批。版本/分支/refspec/registry/package 等身份按字段规范化；完整元组冲突不可被同包名或统一小写吞并。

受控发布在效果前固定全部必需身份；普通完成证明在认证时绑定实际身份及用户约束。两者使用同一身份库而非同一授权流程。准备/诊断与认证/发布核验使用同一快照判据；执行前仍重读 revision、目标、证据、host-lock，防止同 revision 的外部状态变化。

## 9. AC08：显式发布的保留范围

共同的必修发布语义为显式采用、精确目标/候选、单次保留/消费、防重放、超时结果未知及可信回读。Codex 保留现有 release adapter；DSH 将其实际可保护的表面单列，不能因没有相同 Hook 名称就删除共同语义测试。

DSH 本版最低必须提供现有受控 registry publish 表面的完整正反例；Codex 的额外 tag/GitHub Release 表面保留其验收。此最低集合不意味着 DSH 的其他发布方式已受保护：若选定契约还要求未覆盖表面，必须在采用/预检时拒绝该不可履行契约；不能效果后才发现，也不能发出“改用普通 shell”的绕行建议。效果前强制拒绝只适用于Guard实际控制的发布入口以及采用/预检。宿主普通shell/opaque runner等无法拦截的通道没有Guard拦截保证，不能为其签发受控发布认证，也不能建议绕行；助手仍须遵守已采用契约，宿主权限继续生效，不宣称插件是沙箱。

root 的普通 push 不自动成为 release 操作；文档、安装、Skill、模型提案不能暗中激活票据。用户明确切换 release profile 的现有语义不得丢失：profile 选定后须进入相应契约流程，缺契约时相关发布失败关闭，普通无关工作保持原边界。

## 10. AC09：旧会话、协议与回滚

支持 DSH 0.6.3 与现存 legacy 读取边界、Codex 0.13.9 及其已支持旧 schema；P0 从仓库实际消费者清单分配新的协议/schema/hash 身份。不能在旧版本号内改变已签发字节，不能仅升级产品号而沿用不兼容状态语义。

新任务用新普通路径；旧任务通过显式版本边界迁移。保留 journal、根输入、旧证书、旧 qualification 原始事实；旧资格不授予新普通执行。当前单元及必需后代内影响新认证的旧 answered/closed 在终态过滤前复查，needs_review 阻断新认证，但不自动成为普通工具审批或无进展 Stop 循环。无关历史不重开；缺原始来源不推断完成。

旧工具调用不可触发普通 mutation；旧 release 契约、已保留票据和不确定效果必须先核对原身份再恢复，不能因新路径重试未知发布。事务性迁移、重复迁移、崩溃恢复、旧新证据共存均有用例。回滚需匹配旧运行时和旧状态快照；旧运行时不得写新状态。不能安全回滚时只读诊断并前滚，不丢工作数据。

## 11. AC10：共同投影与对齐判据

在 Codex 上游产出可独立运行的 Python reference 和 TS consumer；纯核只接收规范事件与真实 fact，不读期望值、case ID 或宿主专属测试开关决定输出。规范输入、Unicode/数值/排序/canonical bytes/hash 规则在 P0 固定，保留 v1/digest_v3 的旧域。

归一化投影至少比较：来源覆盖与未知余项、类型与约束、工作单元闭包、目标来源和身份、delivery、效果与证明资格、普通路径是否被 Guard 干预、Stop 原因与纠正次数、显式发布状态。宿主 ID 只作确定映射；不能删除有分歧的关键字段来获得相等。普通路径不得出现 Guard 签发的执行权限字段。

同一原始自然语言和同一规范事件序列各有比较泳道：前者测试产品真实解释入口，后者定位核心状态机差异。结构化模型候选输入不能代替原文入口测试。解释不确定允许在扩展集显式记录，但固定必修集须满足独立期望和双端相等；两端都误关闭或都永远 unresolved 不能算通过。

状态台账分两个字段：implementation_status（implemented/partial/missing）和 comparison_status（aligned/measured_difference/not_measured/host_specific）。aligned 必须有共同合同版本、双方源码身份、fixture digest、真实入口层级和结果引用；没有相同 API 名称不构成 host_specific。宿主专属能力只能用于真实不存在的语义需求，不能排除共同要求。过时文字与机器状态矛盾必须作为文档缺陷修复。

## 12. AC11：必修验收家族与停止条件

沿用 C01–C12 / S01–S12 全部适用合同，追加以下结构矩阵；阶段性缺证据不能自行改成 not-applicable。每组同时有正向与反向结果，不穷举自然语言。

| ID | 结构家族 | 必修结果 |
| --- | --- | --- |

独立维护者先冻结期望与核心集/留出集；实现者不能根据实际输出录 golden。固定负例误关闭、错误认证和受控发布错误效果均为零；正向业务路径、纯问答和真实同义表达全部满足预期。发现测试 oracle 错误可单独审议纠正，保留旧结果与理由，不能把产品失败直接重标“边界”。连续第二个同族反例触发入口×动作×字段×状态的集中审计，再统一返还阻断清单。

本地确定性、生产适配器接线、真实模型任务、原生平台及制品是不同证据。四个产品×平台泳道（DSH/Codex 各自 macOS/Windows）分别跑 A12 的受支持业务路径，并在同一真实模型业务中加入 A13 的诚实限制说明及真实剩余动作对照，记录 loaded version/制品身份、根请求、工具轨迹、业务回读、剩余状态、额外澄清与 Guard 开销。使用一次性仓库/profile，明确批准的隔离 push 目标；没有网络目标授权可先做本地 bare remote 源测试，但不得冒充真实跨主机网络验收。模型对话措辞无需相等，核心结果必须符合 oracle。无需 Guard 的额外用户授权轮次在必修无歧义流程中为零；必要平台审批单独统计。

真实模型预算或通道缺失时停止于该门槛，不能用“28 个安装/拒绝检查通过”替代正向任务。配对核心对齐验收要求全部必修泳道完成；一个产品完成可保留候选，但不能宣称已与另一产品对齐。

## 13. AC12：开发、计划审查与发布边界

本轮交付是规划合同及两份计划，不是产品 schema/fixture 冻结或运行时实现。开发 P0 先完成 schema/fixture/reference 接口、消费者及两宿主最低能力清单（真实工具call/result字段、readback、来源信任、持久化水位和平台可用性，至少覆盖AC06正向路径），独立审查后才开始依赖该合同的双端实现；可以先做不依赖新 schema 的有限接口调查。

计划审查固定 authority、identity、state_effect_readback、canonicalization、platform_feasibility、migration_versioning、verification_release_boundary 七个镜头；可复现正确性矛盾、不可实现要求、互操作冲突为 P1。集中返还，修复只复审受影响部分，无开放 P1 和必要机械检查通过即结束本轮计划评审。新镜头/权限来源/缩减必修范围须显式重开，不能在收尾暗中改合同。

本地开发、提交、CI、制品、原生、发布与日常安装分别授权与记账。实施阶段是否提交由当时用户授权决定；本计划不继承其他任务的发布许可。两个产品独立版本和制品身份，协调验收不要求同一天发布。若双方必修核心无法满足，保持未完成或由用户明确改范围，不以单边更多测试宣布对齐。
