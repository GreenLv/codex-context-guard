# 升级到 Context Guard 0.18.0 — 源码候选版

[English](UPGRADE_0_18_0.md) · [日常升级工具](../tools/validation/DAILY_UPGRADE.md)

0.18.0 是尚未发布的源码候选版。对于已安装 0.17.3 稳定入口 `context-guard@codex-context-guard` 的用户，如果工具确认新旧运行时兼容，可以选择在回合间升级。操作工具位于源码仓库，不包含在发行 ZIP 或插件缓存中。候选版尚未发布，请勿把将来的标签或下载附件当作现有资源。

## 准备

保留已核验的上一版 ZIP 和市场来源目录。准备经审查的 0.18.0 候选包目录及对应源码中的操作工具。按[日常升级说明](../tools/validation/DAILY_UPGRADE.md)创建私有计划和结果目录，将它们放在源码仓库及日用配置目录以外。回合间升级计划需要同时指定保留的已核验旧版和新版目录。先运行命令预检与准备。

工具会将已安装旧文件与保留的旧版对照，并检查新版运行时。如果无法确认兼容性、所有权或其他前提，请按拒绝提示处理，不要使用回合间方式。如果插件原本有意保持禁用，请继续保持，直到决定启用。更早版本或其他入口请先阅读 [0.17.3 升级指南](UPGRADE_0_17_3.zh-CN.md)及其链接的更早指南，包括清理设置说明。

## 在回合间切换

等当前回合结束后，暂停开始新操作。保持 Codex 打开，等待已准备的工具确认旧运行时已结束并完成官方市场和插件操作。切换完成前不要开始新回合。官方添加插件可能删除旧缓存；工具不会向已消费缓存复制文件或修复缓存。批次中断时保留同一份计划和记录，按接续提示处理。

原有的退出后升级方式仍可使用。它的 `--resume --wait` 选项可以限时等待宿主退出，不适用于回合间升级计划。无需切换时，直接继续核验，不要重复安装。

## 审核与核验

如有提示，通过官方界面审核新 Hook，再继续核验并恢复原任务。新 CLI 客户端的列表只说明该客户端看到哪些 Hook 定义，不能单独证明旧任务已经继续，也不能证明 Desktop 图形界面已经加载这些 Hook。任务实际执行和图形界面行为需要分别观察。

稳定插件身份和原有数据目录继续使用。已禁用的清理策略、自定义保留期、仅隔离设置和持久关闭记录仍然生效。没有策略时，符合条件的会话在结束 30 天后可进入隔离区，至少隔离 7 天后，后续自动维护才可永久删除。查看、关闭和恢复方法见[会话存储](SESSION_STORAGE.md)。保留已核验旧版与批次记录以备恢复；降级是另一次独立的官方安装操作。
